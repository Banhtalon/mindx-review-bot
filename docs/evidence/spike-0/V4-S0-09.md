# Evidence V4-S0-09 — Encrypted browser state lifecycle

- Date: 2026-08-12
- Commit: `cf17a44`
- Environment: synthetic Python runner with an in-memory object store
- Data class: synthetic
- Requirement: Browser state is encrypted, resettable and unreadable without
  its key.

## Command/steps

1. Add a direct `cryptography` dependency pinned to the existing major version.
2. Run the focused browser-state tests:
   `uv run pytest tests/unit/test_browser_state.py -q`.
3. Run the complete browser-runner checks:
   `uv run ruff check .`, `uv run mypy src`, and `uv run pytest`.

## Expected

Synthetic state is encrypted with AES-256-GCM before storage, uses a fresh
nonce, is bound to `teaching` or `lms`, rejects wrong keys and tampering, and
reset revokes/deletes the active object so the next run must log in again.

## Actual

- Focused browser-state tests passed: 16 tests.
- The complete browser-runner suite passed: 35 tests.
- Round-trip encryption stores only an envelope with `key_version`, `iv`,
  `tag`, `ciphertext` and `state_hash`; the plaintext synthetic state is absent
  from the serialized object.
- Wrong-key, malformed-envelope, tampered-ciphertext, hash and wrong-site
  reads fail closed with `STORAGE_STATE_DECRYPT_FAILED`.
- Saving a new version revokes the previous active metadata version. Key
  version 2 can be activated and loaded with its replacement key.
- Reset revokes the active metadata version and deletes its object from the
  synthetic store. Missing state therefore requires a fresh login.
- Object paths contain only a workspace UUID, the allowlisted site and an
  opaque version UUID; no username, email, credential or cookie is used.
- No real browser state, key, credential, cookie or student data was created.

## Result

- PASS — synthetic encrypted browser-state crypto and save/load/reset lifecycle
  are implemented and tested.
- Live Supabase Storage upload/download and a real Teaching/LMS login remain
  separate owner-controlled gates.
